🎯 What This Is

Cipher-Tube is a modular, zero-trust cryptographic platform centered on secure session management and encryption. The architecture is built on a four-pillar design (Sentinel, Bolt, Palette, Tube) that handles security orchestration, performance/benchmarking, UI/accessibility, and inter-pillar cryptographic transport respectively. It's designed as a node-based system with mythic governance concepts layered on top for operational philosophy.

🔑 Key Purpose: Provide military-grade cryptographic operations with a self-governing digital civilization model featuring five Realms (Pulse, Drift, Shadow, Return, Lineage) guarded by Archetypes.

🛡️ Security-First

AES-256 encryption, session ownership, zero-trust architecture

⚡ High Performance

~0.44ms encryption/decryption, benchmarked with Bolt

♿ Accessible UI

WCAG 2.2 AA, dark mode, design tokens via Storybook

🔄 How It Fits Together

The Cipher-Tube architecture follows a layered, event-driven design:

Request Flow:
1. Express Gateway receives request with x-user-id header
2. Session ownership middleware validates session:{sessionId}:owner in Redis
3. Sentinel orchestrates security scanning (audit, remediation)
4. Bolt performs cryptographic operations (AES-256-GCM, ~0.44ms)
5. Palette renders UI components with accessibility compliance
6. Tube encrypts inter-pillar communication
7. Response returned with encrypted session data

🚀 How to Run It

⚙️ Prerequisites
  • Node.js 20+ (LTS)
  • npm 10+
  • Redis (running locally or via Docker)
  • Docker & Docker Compose (for full dev environment)
📦 Installation
# Install all workspace dependencies npm install --workspaces # or using Make make install
🔧 Local Development
# Start full development environment make dev # Services will be available at: # Sentinel: http://localhost:3001 # Bolt: http://localhost:3002 # Palette: http://localhost:3003 # Tube: http://localhost:3000 # Stop development environment make dev-down # View logs make dev-logs
🧪 Testing
# Run all tests make test # Unit tests only make test-unit # Integration tests (starts Docker services) make test-integration # Specific pillar (sentinel|bolt|palette|tube) make test-unit PILLAR=sentinel
⚡ Performance
# Run benchmarks make benchmark # Compare benchmark results make benchmark:compare
🔒 Security & Quality
# Security scanning make security-scan # Linting make lint # Auto-format code make fmt # Policy validation (OPA) make policy:test make policy:fmt
🌍 Environment Configuration
# Copy example config cp .env.example .env # Key environment variables: REDIS_URL=redis://localhost:6379 BASE_URI=http://localhost:3232 ENABLE_AES256=true # Enable AES-256 encryption NODE_ENV=development
💡 Pro Tip: Use make help to see all available commands. The Makefile supports parameterization for running tests on specific pillars.

✨ Key Features (v1.5.0)

🔐 AES-256 Encryption Support

Military-grade AES-256-GCM with PBKDF2 key derivation, hardware acceleration (AES-NI), configurable encryption modes

🌙 Dark Mode UI

System preference detection, manual override, smooth transitions, WCAG 2.2 AA compliant, battery-saving OLED optimization

🔧 Session Timeout Fix

TTL-respecting session management, activity-based refresh (30-min window), proper Redis cleanup, graceful recovery

🛡️ Per-User Session Ownership

Middleware ensures only owning user can use session, stored as session:{sessionId}:owner in Redis

📊 Performance Optimizations

~0.44ms avg encryption speed, ~2-3% CPU overhead (accelerated), 40% faster timeout detection

♿ Accessibility First

WCAG 2.2 AA compliance, Axe Core auditing, high contrast ratios, screen reader support

🔐 Encryption Specifications
Algorithm: AES-256-GCM
Key Derivation: PBKDF2 with SHA-256
Key Length: 256 bits (32 bytes)
IV Length: 96 bits (12 bytes)
Mode: Galois/Counter Mode (GCM)
Hardware: AES-NI acceleration support
